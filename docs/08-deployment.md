# 08 — Environment & Deployment

## Environment variables (`.env.example`)
```
# server
NODE_ENV=development
PORT=4000
DATABASE_URL=postgresql://getit:getit@localhost:5432/getit
JWT_SECRET=change-me-to-a-long-random-string
DEVICE_SALT=change-me-to-another-long-random-string
CLIENT_ORIGIN=http://localhost:5173
# optional stretch
GEMINI_API_KEY=
```
Validate with zod in `server/src/env.ts`; crash on start with a clear message if something is missing.

## Local
- `docker-compose.yml`: `postgres:16`, user/pass/db `getit`, port 5432, named volume.
- Vite dev server proxies `/api` and `/socket.io` (with `ws: true`) to `http://localhost:4000` → same origin in dev, so cookies just work.
- Phones on the same Wi-Fi: run Vite with `--host` and open `http://<laptop-ip>:5173`. (For the real demo use the deployed URL instead.)

## Production — ONE service (simplest, no CORS problems)
- `npm run build` builds `client/dist`; Express serves it as static files and falls back to `index.html` for client routes. API under `/api`, Socket.io on the same server.
- Host on a platform that supports **long-lived WebSocket connections** and a always-on Node process, e.g. Render, Railway or Fly.io (not serverless functions — Socket.io needs a persistent server). Check the platform's current free/student plans and **avoid plans that sleep** when idle, or wake the service 10 minutes before the demo.
- Database: the platform's managed Postgres or a hosted Postgres (e.g. Neon). Run `prisma migrate deploy` on each deploy.
- HTTPS is required (cookies `secure`, phone cameras opening the QR link).
- Set `trust proxy` in Express behind the platform proxy.
- Single instance only (no horizontal scaling) — enough for a classroom and avoids needing a Socket.io adapter.

## Ready-made: Render Blueprint (`render.yaml`)
The repo contains `render.yaml`: one always-on web service (`npm ci --include=dev && npm run build && npm run db:deploy`, then `npm start`, health check `/api/health`) and a Postgres 16 database. `JWT_SECRET` and `DEVICE_SALT` are generated by Render; set `CLIENT_ORIGIN` to the service URL. In Render: **New → Blueprint →** pick this repo → confirm. Use paid/always-on plans for the demo week (free web services sleep).
- `--include=dev` matters: the platform sets `NODE_ENV=production` during the build, and plain `npm ci` would then skip Vite.
- After the first deploy, load the demo data once: Render shell → `npm run db:seed` (idempotent).
- Railway / Fly.io work the same way (build, migrate, start, health check); only the config file differs.

## Checks
- `npm run smoke -- https://your-app.example` — HTTPS, app page, `/api/health` (DB), CSP header, the QR deep link, and a real WebSocket through the platform's proxy.
- `npm run load-test -- https://your-app.example 60` — 60 simulated phones join, answer and ask at the same moment; prints latencies and verifies nothing was lost or duplicated. Run it once on the deployed service (it creates and ends a session under `load-test@getit.app`, never the demo account).
- `E2E_BASE_URL=https://your-app.example npm run e2e` — the whole Playwright suite (incl. the full demo script) against the deployment.

## Security headers (Phase 7)
Helmet with a strict Content-Security-Policy: scripts only from the app itself (no inline scripts — the theme bootstrap is `/theme-init.js`), images `self data: blob:` (QR codes, Take-away image), WebSocket `connect-src`, no framing. Cookies are `httpOnly`, `SameSite=Lax`, `Secure` in production.
